# Production web UI AG-UI migration inventory

Source inspection: 2026-10-03. Assembly/UI checkout: `../agently-ag-ui`; core checkout: this repository. This is a migration inventory and acceptance contract, not an implementation or a claim that production has already migrated. No external service requests or credentials were used for this inspection.

## Non-negotiable outcome

The existing production web UI, layout, workspace surfaces, Tool Feeds, reporting, approvals, and management operations must continue to work. AG-UI becomes the primary agent interaction and streaming protocol; versioned extensions or suitable existing BFF application services preserve the richer application experience. This is a transport/state migration with no visual redesign and no removed functionality. Rich Agently functionality can use versioned, capability-advertised extensions alongside standard AG-UI messages, activities, tools, interrupts, and state, or explicit supporting application mechanisms. The user allows “other mechanism”; this inventory identifies possible bindings and gaps, not a requirement to replace every HTTP route.

Keep the existing BFF authentication absolutely: same-origin cookie/session flows, provider discovery, local login, OAuth popup/redirect/callback, logout, and MCP OAuth integration remain authoritative. Neither forwarded properties nor iframe JSON may supply authenticated identity or authorization. Public generic AG-UI compatibility must be demonstrated in this same web UI against a known non-Agently AG-UI implementation, as well as against Agently.

## Current wiring and inventory boundaries

- `../agently-ag-ui/ui/src/services/agentlyClient.js:9,187` constructs the legacy `AgentlyClient` with `baseURL: '/v1'`, `useCookies: true`, unauthorized handling, transient-error toasts, and retry settings. No production source imports `AgUiClient` today.
- `../agently-ag-ui/ui/package.json` uses `file:../../agently-core/sdk/ts`; `ui/vite.config.js:102` aliases the package to `../../agently-core/sdk/ts/src`. Both currently select the original core checkout rather than the AG-UI checkout. Assembly `go.mod:200` already replaces core with `../agently-core-ag-ui`. Migration/build proof must resolve this mismatch.
- `sdk/ts/src/agui.ts` exports `AgUiClient`, generic `run`, Agently `runAgently`, capabilities discovery, interrupt resume, client-tool dispatch, full-input replay, and `run.cancel`. It has a generic command-props helper, but no domain SDK bindings for most existing browser resource methods.
- `../agently-ag-ui/ui/src/endpoint.js` gives Forge three endpoint maps. `ui/src/App.jsx:82` installs them and `connectorConfig` into Forge's `SettingProvider`. Metadata-driven datasource calls bypass the singleton JS client.
- `ui/src/connector.js:45-79` configures remote window/navigation metadata and starts HTTP `/v1/ui/rpc` long polling. `App.jsx:29-30` starts the bridge. Replacing only `client.query()` leaves these protocols active.
- Runtime registration is in assembly `serve.go:190-256`: UI view/window/control/feed/datasource/context/events/report services, report orchestration, scheduler, and authenticated API handler are configured together. `serve.go:260,342-355` protects `/window/` metadata; these JSON/YAML definitions are interaction metadata, not automatically exempt static assets.

Legacy BFF CRUD/reporting/metadata/application APIs may remain when suitable and explicitly documented. A missing AG-UI domain binding is a planning gap only if that operation is selected for migration. Primary chat and streaming must migrate. In tables below, **existing binding** means backend dispatch exists in inspected AG-UI code; it does not mean the browser uses it or that all legacy semantics already match. **Partial** means a related binding exists but insufficient coverage is visible. **Missing** means there is no corresponding admitted operation/dispatch in the inspected code. Proposed operation names require architecture/schema approval before implementation.

## Core backend facts that override stale matrix rows

- Dispatch/admission in `sdk/handler_agui_durable.go:107-157` recognizes `goal.*`, `state.*`, `workspace.*`, `datasource.*`, `lookup.*`, `feed.*`, `run.*`, plus the separate MCP Apps proxy. Missing domains cannot work by inventing a forwarded operation name in the web client.
- Capability advertisement in `sdk/agui_capabilities.go` is conditional on configured backend services. `goal.subscribe` and `feed.subscribe` already exist. The older operation matrix's generic “subscription parity remains open” should not be read as absence of these implementations.
- `sdk/ts/src/client.ts:303` still throws for `getRun`, although `run.get` is now implemented. This reinforces that legacy SDK surface, backend dispatch and browser callsites must be reviewed separately.
- `sdk/agui_workspace_metadata.go` supplies seven metadata/catalog/model operations. It does not supply Forge navigation/window/permission definitions or scheduler resources.
- Standard recovery and rich rendering support in `sdk/agui_recovery*.go`, `agui_rendering.go`, `agui_message_updates.go` are valuable foundations. They do not establish execution-group pagination, diagnostics/detail-panel parity or production reducer integration.
- Capability-gated extensions should not silently fall back to old JSON/SSE routes after transport errors. Generic agents may lack Agently extensions; the same shell must keep basic standard chat/tools/interrupts usable and show unavailable extension actions accurately.

## Acceptance requirements

1. **Same product:** compare the existing App/Forge tree, screenshots and interactive behavior before/after. Preserve menu/sidebar, route navigation, typography/layout, composer/lookups, execution workspace, detail/usage panels, hosted windows, Tool Feed placement/pin/select/drafts, reports and settings. No visual redesign or feature regressions.
2. **Standard interoperability:** run this production web UI against Agently and a known public non-Agently AG-UI backend implementation. Exercise streamed text, tool call/result, state/activity projection, interrupt/resume and reconnect where that backend supports them. Record backend project/revision and actual test evidence. A separate CopilotKit example or fake fixture alone does not meet this gate. The generic target uses standard `RunAgentInput` and no required Agently discovery/forwarded extension.
3. **Authentication:** existing BFF login/provider/local/OAuth popup/redirect/callback/logout/MCP OAuth and same-origin session authority continue to pass. Unauthorized protected AG-UI calls trigger the existing recovery/login behavior once. Session recovery/logout clears scoped caches. Forged user/principal/app scope in forwarded props cannot grant authority.
4. **Network boundary:** capture production browser requests for every family above. Primary agent interaction uses AG-UI and no `/agent/query` or legacy `/stream`. For each supporting application family, document the chosen AG-UI extension or retained BFF application API and its reason. Assert that no unintended legacy agent stream/query fallback survives. Include metadata-created calls and background polling; checking only imports is insufficient.
5. **Single protocol authority:** upstream AG-UI reducer owns messages/state/interrupts. Existing ChatStore/rendered turns are a projection. Multipart media, reasoning/tool/activity messages, unknown custom event/version observability, tool IDs and host-only metadata survive without flattening them into chat prose.
6. **Concurrent execution/recovery:** switching chats, refreshing, disconnect/reconnect, replay, background goals, feeds, nested children and client tools preserve event order and ownership. UI controls target the correct protocol/native run mapping. Replay/retry never repeats completed effects. Detach differs from cancel. No completed assistant text reappears or becomes a fabricated extra turn.
7. **Durable user actions:** queued turn edit/move/cancel/force-steer; active steering; compact/prune; title/visibility/delete; scoped conversation/history pagination; report export and callback actions preserve operation identity, authorization, revisions, failure and uncertain-effect reporting. Resource commands do not submit model queries or mutate chat history unintentionally.
8. **Approvals:** recovered pending inbox and in-run interrupts work independently, with concurrent decisions, expiry/rejection/edit, callback execution and outcome receipts. MCP Apps approval returns the exact full host result only after approved execution; unknown/host-only metadata stays out of model messages.
9. **Rich surfaces:** run existing Forge/reporting fence, chart/table, datasource lookup, window authorization, report builder, export/adopt and MCP Apps host tests through the new transport. Validate local draft state versus server persisted state, resource lifecycle/teardown and frame-origin checks. Unsupported extensions stay observable and do not leak raw authoring JSON into assistant prose.
10. **Build/provenance:** production Vite dependency/alias and assembly Go replacement resolve to reviewed AG-UI sources; embedded deployment bundle is regenerated. Preserve all pre-existing uncommitted backend work. Documentation must report remaining missing gates rather than claim complete parity from focused SDK tests.

## Suggested implementation division

1. **Architecture/contracts first:** approve schemas and shared command/subscription adapter, auth fetch policy, standard reducer projection, identity/replay rules and extension capability contracts. Do not settle on a generic REST tunnel inside a custom event.
2. **Core extension/domain bindings:** conversation/history/queue/approval/direct-tool commands; window/navigation/permission/UI bridge; callbacks/reporting/scheduler/preferences. Reuse existing service policy entry points and advertise only wired operations. Separate command runs and subscriptions from model chat runs.
3. **Web transport/projection:** migrate primary agent session and chat runtime, then selected goals/feeds/lookups/resource services; preserve an explicitly scoped BFF application client where suitable. Retain existing renderers and local UI state. Add standard-agent target selection and compatibility behaviors to the same shell.
4. **Forge metadata adapter:** route selected metadata-created datasource/window/navigation/editor operations through typed AG-UI adapters, and document suitable retained application APIs. Coordinate with Forge runtime bridge transport rather than rewriting every YAML definition as an opaque URL envelope.
5. **Product acceptance:** browser network assertions and before/after UI proof across all families; same-shell Agently + public generic backend runs; authentication tests; deployment bundle verification.

Highest-risk dependencies are the chat legacy DTO projection versus standard reducer, metadata-created hidden REST calls, acknowledged UI bridge/device state, global approval inbox semantics, and reporting operation revisions/idempotency. Implementing chat + existing resource SDK wrappers alone does not establish feature parity; these application features still require explicit preservation and acceptance evidence, whether using extensions or retained BFF services.
